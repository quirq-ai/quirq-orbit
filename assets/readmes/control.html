Run commands on a remote machine without opening a port on it.

control has two roles. A controlled node polls a shared queue, checks each job, runs the ones its policy allows and posts signed results. A controller signs jobs, puts them on the queue and reads back verified results. The queue is pluggable: a git repository (any host, private recommended) or a plain directory (local disk, shared mount, synced folder).

 controller                       queue (git repo / dir)                 controlled
 ──────────                       ──────────────────────                 ──────────
 control run -- uname -a  ──►  nodes/box/jobs/<id>.json    ──►  verify signature, check policy,
                                                                 run with a clean env + timeout
 verified output   ◄──────────  nodes/box/results/<id>.json ◄──  redact secrets, sign result
                               nodes/box/results/<id>.log

Nothing runs unless it is signed by a key the node trusts and allowed by the node's policy. The default policy allows nothing.

Status: early (0.1). The message format is versioned ("v": 1).

Install

Requires Node.js 20 or newer. No dependencies.

git clone <this repo> control && cd control
npm test            # optional
npm link            # puts `control` on your PATH

Quick start (git queue)

  1. Create an empty private repository to use as the queue, and clone it on both machines, e.g. at ~/control/queue.

  2. On the machine you want to control:

    control init --role controlled --node box --dir ~/control --transport git --queue queue

  3. On your machine:

    control init --role controller --name alice --dir ~/control --transport git --queue queue

  4. Exchange public keys (keys/<name>.pub, safe to share; the .key files never leave their machine):

    # on box, with alice.pub copied over
control trust alice.pub --name alice --config ~/control/control.json
# on alice's machine, with box.pub copied over
control trust box.pub --name box --config ~/control/control.json

  5. Edit the node's policy in ~/control/control.json (see below), then start it:

    control serve --role controlled --config ~/control/control.json

    For a service that survives reboots, see examples/control-controlled.service.

  6. Run something:

    export CONTROL_CONFIG=~/control/control.json
control run -- uname -a                 # waits and prints the output
control run --no-wait -- df -h          # prints the job id
control status <id>
control logs <id>
control list
control cancel <id>                     # only before it starts
control serve --role controller         # follow every new result as it lands

Policy

The node decides what it will run. Rules match the program name exactly (argv[0]), then the arguments:

"policy": {
  "allow": [
    { "command": "uname", "args": ["-a"] },
    { "command": "git", "argsPrefix": ["-C", "/srv/app", "pull"] },
    { "command": "uptime" }
  ],
  "scripts": false,
  "workdirs": ["~", "/srv/app"],
  "defaultTimeoutSeconds": 300,
  "maxTimeoutSeconds": 3600,
  "passEnv": ["LANG"],
  "jobEnv": [],
  "maxOutputBytes": 1048576
}
Rule Allows
args: [...] exactly these arguments
argsPrefix: [...] these first arguments, anything after
neither any arguments (you trust that program completely)

"scripts": true lets trusted controllers send whole shell scripts (control run --script deploy.sh). That is full shell access as the node's user: use it for a machine you own end to end, never on a shared host.

Jobs run without a shell (for argv jobs), in a fresh environment that holds only PATH (from the policy), HOME, the passEnv variables and job variables named in jobEnv. The working directory must resolve, through symlinks, inside workdirs.

Secrets

  • Private keys are created with mode 0600, never overwritten, and refused if others can read them.
  • Logs are redacted on the node before they are written to the queue: common token formats (GitHub, AWS, sk- API keys, Slack, JWTs, bearer headers, URL passwords, PEM private keys, NAME=secret style assignments), the values of the node's own environment variables whose names look secret, and anything listed under redact.env / redact.patterns. Redaction is a safety net, not a guarantee: do not run jobs that print secrets.
  • Job payloads and results are signed, not encrypted. Anyone who can read the queue can read them, so keep a git queue private.

Exit codes

control run (waiting) and control status exit with the job's own exit code, or: 124 timed out, 130 cancelled, 2 rejected / error / result failed verification, 3 no result yet, 1 usage or config error, 64 unknown command.

Transports

Type Use it for Config
git machines that can both reach a git host { "type": "git", "path": "<clone>", "remote": "origin", "branch": "main" }
dir one machine, a shared mount, or a synced folder { "type": "dir", "path": "<dir>" }

Others (HTTP, object storage) can be added with registerTransport; see DESIGN.md.

Library

import { Controller, Controlled, loadConfig } from 'control';
const ctl = await new Controller(loadConfig('control.json')).start();
const job = await ctl.submit({ argv: ['uname', '-a'] });
const r = await ctl.wait(job.node, job.id, { timeoutMs: 60000 });
if (r?.verified) console.log(r.result.status, r.log);
